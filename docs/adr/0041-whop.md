# ADR-041: Whop connector (checkout links, members, real sales)

**Status:** accepted, 2026-11-27

## Decision
Whop is the only place Jackson takes course money, and the only source of course revenue and student numbers.

- **API:** Whop's current REST v1 (`https://api.whop.com/api/v1`). Calls use `Authorization: Bearer WHOP_API_KEY` and pin `Api-Version-Date: 2026-11-25`, so response shapes don't change underneath us. Money is read as Whop's `{amount: "49.00"}` dollars and stored as cents.
- **Test:** `GET /accounts/me`. It is read-only.
- **Sync** (worker task `whop_sync`, the "Sales Recorder" on the Courses building's Sales & Launch floor):
  - Reads memberships and payments, newest first: up to 50 pages of 100, then the webhook keeps it current.
  - Each membership is upserted into `whop_members`. Linked Discord and Telegram ids are never wiped by a webhook, which carries none.
  - Each **paid** payment becomes one `revenue_entries` row: source `whop`, kind `actual`, reference `whop:<payment id>`. A partial unique index on `(tenant_id, reference) WHERE source = 'whop'` makes the webhook and the sync idempotent together.
  - A refund adds only the newly refunded amount, as kind `refund`.
- **Webhook:** `POST /webhooks/whop/{tenant}` uses Standard Webhooks signatures (`webhook-id`, `webhook-timestamp`, `webhook-signature`) with a 5 minute tolerance. Unsigned, bad or stale requests get a 401. It handles:
  - `payment.succeeded`
  - `refund.created`, which re-reads the payment
  - `membership.activated` and `membership.updated`
- **Which business:**
  1. The payment's metadata. Jackson's checkout links carry `jackson_business_id`.
  2. Otherwise, an owner-made link from a plan or product to a business (`whop_links`).
  3. Otherwise none: the sale counts in totals and never lands on the wrong business.
- **Checkout:**
  - `POST /tenants/{t}/whop/links` with a course and a plan id asks Whop for a checkout configuration and stores its `purchase_url`.
  - The course's sales page swaps its "Nothing can be bought" placeholder for an **Enroll now** link.
  - Nothing is charged by Jackson, since Whop runs the checkout. Publishing the page is still a launch decision.
- **KPIs:**
  - Courses: "Students with access (Whop)" and "Course revenue this month (Whop)". Revenue is now counted by the payment's month (`period`), not by when Jackson recorded it.
  - Community: "Paying members" and "Members with Discord linked".
  - With no Whop data, each KPI shows "no data" and never zero.

## Data
- `whop_links`: the app can insert and read; the worker can read.
- `whop_members`: unique per tenant and membership. The app (webhook) and the worker (sync) can both insert and update.
- The worker gains INSERT on `revenue_entries`, which stays append-only.
- Every table uses RLS by tenant.

## Without keys
- No `WHOP_API_KEY`: sync and checkout links are refused with the variable name, the course pages stay drafts, and the KPIs say no data.
- No `WHOP_WEBHOOK_SECRET`: the webhook answers 503. A sync still works.
